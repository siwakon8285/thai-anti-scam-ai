# การทดลองประมวลผลข้อความภาษาไทย V0.1

TASK-005-R1 · **RESEARCH_COMPLETE_PENDING_REVIEW**

## 1. วัตถุประสงค์

ศึกษาว่าการปรับรูปข้อความช่วยให้รูปเขียนที่ควรเทียบเท่ากันจับคู่ได้มากขึ้นเพียงใด และยังรักษาความต่างของคำปฏิเสธ เครื่องหมายคำพูด ตัวเลข URL และ Unicode ที่มีผลต่อการตีความหรือไม่ ผลใช้ทบทวน Input Contract และเลือกวิธีสำหรับ Matching View ในอนาคต

## 2. วิธีทดลอง

- กำหนด Case ID, Expected Outcome และเหตุผลในสคริปต์ก่อนรัน ใช้ข้อความสมมติแยกจาก Development Dataset รายงาน JSON เก็บค่าคาดหวัง ผลจริง รายการ code points และรายละเอียดการวัด สตริงที่มี surrogate แทนด้วย code points และช่อง text เป็น null เพื่อให้ JSON ใช้ UTF-8 ได้ [สคริปต์](../scripts/experiments/text_processing.py) · [รายงาน JSON](../reports/text-processing-v0.1.json)
- **EXP-001** เทียบ Raw, NFC, NFKC, NFD และ NFKD กับค่าที่กำหนดไว้ ตรวจความยาว ความเท่ากันและ idempotence พร้อมคู่ทดสอบ canonical และ compatibility equivalence ตาม UCD 16.0.0
- **EXP-002** ตรวจ strip(), isspace(), collapse, casefold, การลบเครื่องหมายที่ระบุ, การตรวจตำแหน่ง control/format/surrogate/variation selector และ strict UTF-8 แยกกัน สำรวจการแบ่งคำด้วย split() และ Regex word chunks
- **EXP-003** เทียบความเท่ากันหลังแปลงทั้งสองด้าน และรัน Regex ตัวอย่างคงที่แยกจากการเทียบคู่ นับความต่างที่ยังคงอยู่จาก protected pairs ส่วน Regex span อ้างตำแหน่งใน Matching View คู่ภาษาพูด, ZWSP กลางคำ และ BOM ต้นข้อความอยู่ในกลุ่ม Open Question
- **EXP-004** ใช้ CPython 3.14.8 / UCD 16.0.0 บน macOS 27.2.1 / Apple M4 / arm64 / RAM 16 GiB วัด 17 ปฏิบัติการบนข้อความไทย อังกฤษ ผสม และ Unicode ซับซ้อน ขนาด 128, 512, 2,048, 8,192 และ 32,768 code points รวม 340 จุดวัด ทำ warm-up 8 ครั้ง จากนั้น timeit 7 รอบ รอบละ 100 ครั้งถึง 2,048 code points และ 25 ครั้งสำหรับขนาดใหญ่กว่า รายงาน median และ median absolute deviation (MAD) วัด peak traced allocations แยกจากเวลา 3 รอบ รอบละ 1 ครั้ง แล้วเก็บค่าสูงสุด โดยสร้าง Input นอกช่วงที่เปิด tracemalloc

## 3. ผลสำคัญ

- **EXP-001** ตรงค่าคาดหวัง 64/64 รวม 60 การตรวจผลต่อรูปข้อความและ 4 คู่ equivalence ทุกรูปที่ทดลองผ่าน idempotence NFC และ NFD รวมคู่ canonical เช่น é กับ e ตามด้วย combining acute NFKC และ NFKD ยังรวมรูปสระอำกับรูปแยกและเลขวงกลมกับเลขปกติ การเปลี่ยน code points ของสระอำช่วยจับคู่ตัวอย่างที่อ่านเหมือนกัน ส่วนเลขวงกลมเป็นหลักฐานด้านรูปแบบที่สูญจาก Matching View เมื่อเกิดการรวม
- **EXP-002** ตรงค่าคาดหวัง 24/24 ได้แก่ whitespace sweep, 20 กรณี Input และ 3 ตัวอย่าง segmentation Python ให้ isspace() และ strip() ตรงกันสำหรับข้อความหนึ่ง code point ทั้งช่วง 0 ถึง U+10FFFF โดยพบ whitespace 29 code points เทียบกับ Unicode White_Space 25 ตัว ส่วนเพิ่มคือ U+001C–U+001F สตริงว่างให้ isspace() เป็น False ขณะที่ strip() คืนสตริงว่าง
- **EXP-002** BOM, ZWSP, ZWJ, ZWNJ และ VS16 ที่ทดลองยังอยู่หลัง strip() NUL และ ESC เข้ารหัส UTF-8 ได้แม้ Contract อาจปฏิเสธ ส่วน surrogate เดี่ยวและคู่ที่ยังเก็บเป็นสอง surrogate code points เข้ารหัสแบบ strict ไม่ได้ split() ไม่แบ่ง “ภาษาไทย” และ Regex word chunks แยก “สวัสดีครับ” เป็น “สว / สด / คร / บ” จึงควรศึกษา Thai Word Segmentation แยกจากการจัด whitespace
- **EXP-003** ประเมิน 8 คู่ที่ควรเท่าและ 8 คู่ที่ต้องต่าง พร้อม Regex probes 8 กรณี ผลเปรียบเทียบอยู่ในตารางด้านล่าง เคสเปิด 3 คู่แสดงผลรายเทคนิคใน JSON แยกจากคะแนน
- **EXP-004** รันชุดเต็มสองครั้ง ผลเชิงพฤติกรรมของ EXP-001–003 ตรงกันทุกค่า โครงสร้างจุดวัดและค่า peak traced allocations ตรงกัน 340/340 จุด ค่ามัธยฐานเวลาระหว่างรอบต่างกันมัธยฐาน 2.73% และมากสุด 35.94% โดยเทียบผลต่างกับค่าที่น้อยกว่าของแต่ละจุด รายงาน JSON เก็บการวัดชุดแรก

## 4. ตารางเปรียบเทียบ

| เทคนิค | คู่ที่ควรเท่าที่รวมได้ / 8 | คู่ที่พลาด / 8 | Collision / 8 | ความต่างที่รักษาได้ / 8 | Regex ตรงคาด / 8 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Raw | 0 | 8 | 0 | 8 | 5 |
| NFC | 2 | 6 | 0 | 8 | 6 |
| NFD | 2 | 6 | 0 | 8 | 5 |
| NFKC | 4 | 4 | 1 | 7 | 6 |
| NFKD | 4 | 4 | 1 | 7 | 5 |
| strip() | 1 | 7 | 0 | 8 | 6 |
| Whitespace collapse | 2 | 6 | 1 | 7 | 6 |
| Casefold | 1 | 7 | 1 | 7 | 4 |
| ลบเครื่องหมายที่ระบุ | 1 | 7 | 2 | 6 | 2 |
| strip() + NFC | 3 | 5 | 0 | 8 | 7 |
| strip() + NFKC | 5 | 3 | 1 | 7 | 7 |
| strip() + NFKC + casefold | 6 | 2 | 2 | 6 | 5 |

NFKC ช่วยคู่สระอำและ fullwidth แต่รวม ① กับ 1 การ collapse รวม newline กับช่องว่าง Casefold รวม URL path ต่างตัวพิมพ์ การลบเครื่องหมายช่วยคู่คำทักที่ลงท้ายด้วย ! แต่ทำให้จุดทศนิยมและขอบเขตคำพูดหาย Regex probes ตรึงรูป Pattern เดิม จึงสะท้อนความเข้ากันได้กับ Pattern นั้น เช่น NFD คืนรูปแยกเมื่อ Pattern ต้องการ é รูปประกอบ คะแนนทั้งหมดเป็นผลเทียบข้อความสมมติ

| ไทย | strip() + NFKC | 1,037.99 | 12.55 | 266,310 |
| อังกฤษ | strip() + NFC | 0.35 | 0.002 | 32,807 |
| ผสม | strip() + NFC | 904.59 | 2.49 | 262,284 |

| Unicode ซับซ้อน | strip() + NFC | 1,103.76 | 2.05 | 393,340 |
| Unicode ซับซ้อน | strip() + NFKC | 1,047.40 | 18.97 | 393,340 |

ความเร็วขึ้นกับรูปข้อความและจำนวนผลที่ต้องสร้าง เช่น NFC บน seed ไทยที่ใช้มีต้นทุนต่างจาก seed ผสมอย่างมาก ที่ขนาด 128 code points ค่า strip() + NFC อยู่ที่ 0.14 µs บน seed ไทยและ 4.51 µs บน seed Unicode ซับซ้อน ค่า tracemalloc ครอบคลุม Python allocations ที่ติดตามได้และไม่รวม Total Process RAM ชุดวัดนี้ไม่รวมต้นทุน Engine, การตรวจ Pattern จริง หรือ concurrent traffic

## 5. ข้อเสนอและข้อจำกัด

| ประเด็น | ข้อเสนอรอเจ้าของโครงการทบทวน |
| --- | --- |
| Non-string | ใช้ TypeError โดยไม่แปลงชนิดอัตโนมัติ การรับ str subclass ยังเปิดเพราะอาจ override เมธอด ประเด็นชนิดข้อมูลมาจาก Contract เดิมและยังไม่ได้ทดลอง dispatch |
| Whitespace-only | ตรวจ scalar และ controls ก่อนตรวจข้อความว่าง ให้ EMPTY_INPUT สำหรับสตริงว่างหรือ Unicode White_Space ล้วน เสนออนุญาต Cc กลุ่ม U+0009–U+000D และ U+0085 ตามชุดนี้ และปฏิเสธ U+001C–U+001F ก่อน trim เพื่อป้องกันการจำแนก control-only เป็นว่าง |
| Invisible characters | รักษา BOM ที่อยู่ใน str, ZWSP, ZWJ, ZWNJ และ variation selectors และตรวจตามบริบท กลุ่ม format-only ที่ผ่านการตรวจอาจคืน UNKNOWN โดยยังต้องตกลง bidi, BOM ต้นข้อความและการรายงานตำแหน่ง |
| Invalid Unicode และ controls | เสนอ ValueError สำหรับ surrogate code points และ Cc นอกกลุ่มที่อนุญาต เช่น NUL หรือ ESC การเข้ารหัสสำเร็จเพียงอย่างเดียวไม่ตรวจข้อกำหนด controls |
| Raw Text Preservation | เก็บ Raw ในหน่วยความจำเฉพาะการเรียกและแยก Matching View ตำแหน่งของ Regex อาจเปลี่ยนหลังแปลง ควรออกแบบการอ้างกลับ Raw ก่อนนำ span ไปใช้จริง |
| Normalization | ใช้ Raw เป็นตัวควบคุมและเสนอ strip() + NFC หลังตรวจ Input เป็นตัวเลือกแรกสำหรับทดสอบต่อ เพราะรักษาความต่าง 8/8 ในชุดทดลองและช่วยคู่ canonical ส่วนสระอำรูปแยกและ fullwidth ควรทดลองการเทียบเฉพาะบริบทก่อนใช้ NFKC หรือ casefold กว้าง |
| Long inputs | ใช้ความยาว Raw เป็น code points เมื่อกำหนดเพดาน และแยก byte budget ของ Adapter การตัดข้อความอาจลบเงื่อนไขหรือหลักฐาน กำหนดเพดานหลังวัดเส้นทาง Engine จริงและตกลงงบทรัพยากร |

## 6. วิธีรันซ้ำ

รันจาก Repository Root คำสั่งแรกส่ง JSON ครบทั้งสี่การทดลอง คำสั่งที่สองตรวจเฉพาะพฤติกรรม หาก EXP-001 หรือ EXP-002 ไม่ตรงผลคาดหวัง สคริปต์จะแสดงรายงานและคืน Exit 1

~~~sh
python3 -B -m scripts.experiments.text_processing
python3 -B -m scripts.experiments.text_processing --behavior-only
~~~

บน Python/UCD เดียวกัน ให้เทียบ Synthetic Fixture SHA-256, ค่าคาดหวัง ผลจริง และคะแนนของ EXP-001–003 กับรายงานเดิม สำหรับ EXP-004 ให้เทียบ Input sizes และ SHA-256 ของข้อความที่สร้าง โครงสร้างจุดวัด และการกระจายเวลา/หน่วยความจำ ค่ามัธยฐานเวลาเปลี่ยนได้ระหว่างการรัน
