# ข้อกำหนดพฤติกรรม AI V0.1

V0.1 เป็นข้อกำหนดสำหรับต้นแบบบทสนทนาภาษาไทยแบบใช้กฎ รองรับข้อความหนึ่งรายการต่อครั้งและคืน Intent เดียว ใช้เอกสารนี้และ [Development Dataset v0.1](../datasets/development/v0.1.json) เป็น Test Specification สำหรับ Branch ถัดไป งาน TASK-004 ยังไม่มี AI Engine หรือ Runtime API ให้เรียกใช้

## Intent Taxonomy

| Intent | ความหมายและขอบเขตที่รองรับ | ตัวอย่างข้อความ | พฤติกรรมที่คาดหวัง | ตัวอย่างที่ไม่เข้า Intent และข้อจำกัด |
| --- | --- | --- | --- | --- |
| `GREETING` | การทักทายเพื่อเริ่มบทสนทนา รองรับคำทักทายไทยทั่วไปและคำลงท้ายสุภาพ | “สวัสดีครับ”, “หวัดดี” | ทักทายกลับเป็นภาษาไทยอย่างเหมาะสม | “แล้วพบกันใหม่ครับ” เป็น `FAREWELL` การอ้างถึงคำทักทายเฉย ๆ อยู่นอกขอบเขต |
| `BOT_IDENTITY` | การถามชื่อหรือถามว่าคู่สนทนาเป็นใครหรือเป็นบอตหรือไม่ | “คุณคือใคร”, “คุณชื่ออะไร” | แนะนำตัวว่าเป็นต้นแบบบอตภาษาไทยแบบใช้กฎของโครงการ | “คุณทำอะไรได้บ้าง” เป็น `BOT_CAPABILITIES` การถามตัวตนบุคคลอื่นอยู่นอกขอบเขต |
| `BOT_CAPABILITIES` | การสอบถามว่าระบบทำอะไรได้บ้างหรือรองรับการสนทนาเรื่องใด | “คุณช่วยเรื่องอะไรได้บ้าง”, “ขอบเขตความสามารถของคุณคืออะไร” | อธิบายขอบเขตที่รองรับจริงและระบุว่ายังตรวจจับการหลอกลวงไม่ได้ | “ช่วยฉันหน่อย” เป็น `HELP` ไม่มีการรับประกันว่างานเฉพาะทางจะทำได้ |
| `THANKS` | การขอบคุณโดยตรง รองรับวลีขอบคุณภาษาไทยทั่วไป | “ขอบคุณครับ”, “ขอบใจนะ” | ตอบรับคำขอบคุณอย่างสุภาพ | คำขอบคุณแบบประชดอยู่นอกขอบเขต “ขอบคุณครับ ช่วยเริ่มให้หน่อย” เป็น `HELP` ตามกรณีที่อนุมัติใน R6 |
| `FAREWELL` | การกล่าวลาหรือแจ้งว่าต้องการจบบทสนทนา | “ลาก่อน”, “ขอตัวก่อนนะ” | กล่าวลาอย่างสุภาพ | “สวัสดีตอนเช้าค่ะ” เป็น `GREETING` การกล่าวลามีผลเฉพาะข้อความตอบกลับ |
| `HELP` | การขอความช่วยเหลือทั่วไปหรือขอคำแนะนำเพื่อเริ่มต้น โดยยังไม่ระบุงานเฉพาะด้าน | “ช่วยฉันหน่อย”, “ช่วยแนะนำวิธีเริ่มต้นหน่อย” | เสนอวิธีเริ่มต้นหรือถามว่าต้องการความช่วยเหลือด้านใด โดยยกตัวอย่างสิ่งที่รองรับได้ | “คุณช่วยเรื่องอะไรได้บ้าง” เป็น `BOT_CAPABILITIES` ส่วน “ช่วยบอกสูตรทำขนมครกหน่อย” เป็น `UNKNOWN` เพราะเป็นคำขอเฉพาะด้านนอกขอบเขต |
| `UNKNOWN` | ข้อความที่มีเนื้อหาแต่เจตนาไม่อยู่ในขอบเขตหรือคลุมเครือจนจำแนกอย่างเหมาะสมไม่ได้ | “วันนี้ฝนจะตกไหม”, “เล่านิทานเรื่องกระต่ายให้ฟังหน่อย” | แจ้งข้อจำกัดหรือชวนระบุคำขอที่รองรับ โดยไม่แต่งข้อเท็จจริงและไม่แสร้งว่าทำงานนั้นได้ | ข้อความว่างเป็น `EMPTY_INPUT` และคำขอความช่วยเหลือทั่วไปที่ชัดเจนเป็น `HELP` การจัดกลุ่มนี้ไม่ได้ประเมินความเสี่ยงจากการหลอกลวง |
| `EMPTY_INPUT` | สตริงว่างหรือสตริงที่มีเพียง whitespace เช่น ช่องว่าง แท็บ และขึ้นบรรทัดใหม่ | `""`, `" "`, `"\t"` | แจ้งให้ผู้ใช้ป้อนข้อความ | “วันนี้ฝนจะตกไหม” เป็น `UNKNOWN` เพราะมีเนื้อหา ชนิดข้อมูลอื่น เช่น `None` อยู่นอกขอบเขตการสนทนา |

เมื่อข้อความถามว่า “คุณคือใคร” ให้พิจารณาว่าเป็นคำถามเรื่องตัวตน เมื่อถามว่า “คุณช่วยเรื่องอะไรได้บ้าง” เป็นคำถามเรื่องขอบเขตระบบ และเมื่อขอว่า “ช่วยฉันหน่อย” เป็นการขอความช่วยเหลือโดยตรง เกณฑ์นี้ใช้ระบุพฤติกรรมที่ต้องทดสอบใน Branch ถัดไป

## Input/Output Contract

- **Input** รับ built-in `str` หนึ่งค่า คืน `TypeError` สำหรับชนิดอื่นรวมถึง subclass ตรวจอักขระก่อน trim และคืน `ValueError` สำหรับ surrogate, `Bidi_Control` และ `Cc` นอกกลุ่ม TAB/LF/CR ข้อความว่างหลังตรวจและ trim เป็น `EMPTY_INPUT`
- **Matching** ใช้ `strip() + NFC` โดยคง BOM, ZWSP และ combining marks กรณี BOM นำคำทัก, ZWSP กลางคำ และ combining mark ล้วนที่ระบุใน R6 เป็น `UNKNOWN / no_match` ส่วน ZWSP เดี่ยวเป็น `UNKNOWN / format_only`
- **Output** ใช้ frozen dataclass พร้อม Runtime Validation สำหรับ `intent`, `response` และ `rule_id` กฎที่ชนะให้รหัสจริง ส่วน `no_match`, `format_only`, `ambiguity` และ `EMPTY_INPUT` ใช้ `None` (`null` ใน JSON)
- **ข้อความตอบกลับ** ตรวจจากความหมายและถ้อยคำที่อนุมัติใน Regression Specification ซึ่งระบุพฤติกรรมเป้าหมายของ V0.1 [Regression Specification](v0.1-regression-spec.md)

V0.1 ยังไม่รองรับ Session Memory การแก้คำสะกดผิดที่ซับซ้อน หลายเจตนาในข้อความเดียว General Knowledge หรือ Scam Detection

## การใช้กรณีทดสอบ

Development Dataset v0.1 มีข้อความสมมติ 32 รายการ แบ่งเป็น 8 Intent ประเภทละ 4 รายการ แต่ละรายการบันทึก `id`, `input`, `expected_intent` และ `expected_behavior` เพื่อกำหนดพฤติกรรมที่คาดหวัง ส่วนข้อมูลระดับชุดระบุ `version`, `purpose` และรายการ `samples` ชุดนี้ใช้พัฒนาและเทียบ Baseline ผลบนชุดนี้สะท้อนตัวอย่างที่ทีมรู้จักอยู่แล้ว การประเมินอิสระต้องใช้ชุดแยกที่ไม่ถูกใช้ปรับกฎ

TASK-004 ตรวจการโหลดและโครงสร้าง Dataset และตรวจการคำนวณของ Evaluator เมื่อมี Engine ใน TASK-005 จึงนำ Test Specification นี้มาสร้าง Behavioral Regression Tests ที่รันจริงใน CI
